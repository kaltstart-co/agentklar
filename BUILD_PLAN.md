# Build plan

The old application has been replaced. Git retains its source. This plan describes the new implementation only.

1. **Current slice:** one local TypeScript service, a small React support UI, durable SQLite records, MCP stdio bridge, explicit projects and roles, and native Codex and Claude Code worker adapters. Claude’s live worker success remains unverified. Keep the existing harness as the user's starting point.
2. **Shared context, delivered:** a bounded project brief, manually saved memory, and next steps shared through the local UI and MCP. Revision conflicts keep the UI draft. Each task retains its launch context. Local browser checks and a real Codex worker verified this flow; memory collection is explicit.
3. **Other harnesses:** add Gemini CLI, Cursor, OpenCode, Muse, and GLM through ZCode workers only after verifying their real native interfaces, authentication, lifecycle, and permission behavior. Muse and ZCode apps are installed locally, but their worker interfaces have not been verified. Discovered CLI or app presence does not prove worker support.
4. **Native project setup:** start with separate Codex and Claude Code instruction file support. The local UI reads the actual root AGENTS.md or CLAUDE.md, previews explicit edits, applies them with a file conflict check, and offers guarded undo. Local browser checks verified separate files, conflict drafts, and draft retention across view changes, harness changes, and reconnects. Each harness keeps its native file and loading rules. Add other harnesses when needed. Configurations, skills, and plugin management remain pending; preserve existing entry points and files.

   Reuse existing tools when later work needs them. [Vercel Skills](https://github.com/vercel-labs/skills) (MIT) offers multi-harness install, list, find, update, and remove commands. A version-pinned CLI is a candidate for skill management; integration is untested. [Ruler](https://github.com/intellectronica/ruler) (MIT) offers rules, MCP, and skills propagation with dry run and revert. Consider it only if explicit sharing is wanted. Its writes can also affect .gitignore and MCP setup, so bounded preview and rollback need review first. This slice uses native files and standard libraries; neither tool is installed.
5. **Model choice:** native Codex and Claude model lists and explicit model selection are verified in the local UI and MCP. Native Codex account allowance has initial coverage. Claude allowance remains unavailable. Limited deterministic model advice is delivered. UI and MCP checks verified advice using native metadata; these checks used no model inference. The policy uses saved cost preference, supplied task complexity, native availability and source-based family profiles. Task and role pins take priority. The main harness can classify the task with its existing model and request advice through MCP; the router uses no extra inference. The optional UI applies a suggestion only when requested. Automatic execution, routing and measured quality benchmarks remain pending. Keep actual usage separate from estimates; cost preference alone is not evidence of model quality.

   Reuse [models.dev](https://models.dev/api.json), an [MIT project](https://github.com/anomalyco/models.dev), for model specifications and API price references. It does not describe subscription usage or rank model quality. [SWE-bench Bash Only](https://www.swebench.com/) uses a fixed mini-SWE-agent environment for comparable coding scores; other leaderboard entries can mix model and harness effects. [Artificial Analysis](https://artificialanalysis.ai/data-api/docs) provides versioned intelligence, coding, and agent scores, but requires an API key, including its free model endpoint. Core AgentKlar should not require a new paid service. Future benchmark imports must keep the exact model and effort, source, date, method, and version. Missing scores stay unknown; never copy a successor model's score to an older model.

6. **Longer workflows:** support lead and worker coordination, review and fix loops, explicit handoff, and more worker concurrency when real work needs them. Avoid a forced completion ceremony.
7. **Reach and setup:** explicit local UI MCP setup now supports Codex User scope and Claude Code Local project scope. Settings reads status, previews the exact native command and destination, applies it with a fresh config check, and offers undo only for its unchanged managed entry. The bridge uses absolute Node/tsx/source paths and the running service home and port. MCP cannot read or change this setup. Existing entries and other native scopes stay under native settings. Automated fixtures and a real SDK handshake verify the bounded paths without inference; installed-native CLI and browser evidence are recorded separately. Add automatic service startup, secure device pairing, and remote access after the local permission and ownership boundaries are proven. The hosted UI currently has no connection to localhost.

Do not add an LLM gateway, API key requirement, chat, editor, or browser. Build one verified path before widening the adapters.
