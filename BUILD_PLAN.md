# Build plan

The old application has been replaced. Git retains its source. This plan describes the new implementation only.

1. **Current slice:** one local TypeScript service, a small React support UI, durable SQLite records, MCP stdio bridge, explicit projects and roles, and native Codex and Claude Code worker adapters. Claude’s live worker success remains unverified. Keep the existing harness as the user's starting point.
2. **Shared context, delivered:** a bounded project brief, manually saved memory, and next steps shared through the local UI and MCP. Revision conflicts keep the UI draft. Each task retains its launch context. Local browser checks and a real Codex worker verified this flow; memory collection is explicit.
3. **Other harnesses:** add Gemini CLI, Cursor, OpenCode, Muse, and GLM through ZCode workers only after verifying their real native interfaces, authentication, lifecycle, and permission behavior. Muse and ZCode apps are installed locally, but their worker interfaces have not been verified. Discovered CLI or app presence does not prove worker support.
4. **Native project setup:** separate Codex and Claude Code instruction files are supported. The local UI previews guarded edits and undo for root AGENTS.md and CLAUDE.md. Project skills can be installed from one named GitHub skill with a staged preview, then removed if every managed file and folder still matches. Codex uses .agents/skills; Claude Code uses .claude/skills. Add other harnesses, skill updates, global skills, and plugin bundles only when needed.

   Project skill staging uses pinned [Vercel Skills](https://github.com/vercel-labs/skills) 1.7.0 (MIT) inside a private service folder. Only the reviewed skill folder is copied to the selected project. Its staged lock file is not copied; AgentKlar keeps separate per-harness ownership in SQLite. [Ruler](https://github.com/intellectronica/ruler) (MIT) remains a possible future tool for explicit cross-harness sharing. Its writes can affect .gitignore and MCP setup, so it is not part of this slice.
5. **Model choice:** native Codex and Claude model lists, explicit model selection, and deterministic routing at task launch are implemented in the local UI and MCP. Native Codex account allowance has initial coverage. Claude allowance remains unavailable. The policy uses saved cost preference, supplied task complexity, native availability and source-based family profiles. Task and role pins take priority. The main harness can classify the task with its existing model and request automatic routing in `task_start`; the router uses no extra inference. The UI defaults to automatic choice for new tasks and offers manual/native default. Measured quality benchmarks and verified savings remain pending. Keep actual usage separate from estimates; cost preference alone is not evidence of model quality.

   Reuse [models.dev](https://models.dev/api.json), an [MIT project](https://github.com/anomalyco/models.dev), for model specifications and API price references. It does not describe subscription usage or rank model quality. [SWE-bench Bash Only](https://www.swebench.com/) uses a fixed mini-SWE-agent environment for comparable coding scores; other leaderboard entries can mix model and harness effects. [Artificial Analysis](https://artificialanalysis.ai/data-api/docs) provides versioned intelligence, coding, and agent scores, but requires an API key, including its free model endpoint. Core AgentKlar should not require a new paid service. Future benchmark imports must keep the exact model and effort, source, date, method, and version. Missing scores stay unknown; never copy a successor model's score to an older model.

6. **Longer workflows:** support lead and worker coordination, review and fix loops, explicit handoff, and more worker concurrency when real work needs them. Avoid a forced completion ceremony.
7. **Reach and setup:** explicit local UI MCP setup supports Codex User scope and Claude Code Local project scope. Settings reads status, previews the exact native command and destination, applies it with a fresh config check, and offers undo only for its unchanged managed entry. The bridge uses absolute Node/tsx/source paths and the running service home and port. MCP cannot read or change this setup. Existing entries and other native scopes stay under native settings. macOS background startup now uses a per-user [launchd LaunchAgent](https://support.apple.com/guide/terminal/script-management-with-launchd-apdc6c1077b-5d5d-4d35-9c19-60f2397b2369/mac) from this checkout. The private CLI can install, check, open, stop, start and uninstall it. Stopping refuses active work unless forced; restart marks unfinished workers interrupted. Native harness settings and sign-in are untouched. Other systems still use `npm start`. Packaging, secure device pairing and remote access remain future work. The hosted UI has no connection to localhost.

Do not add an LLM gateway, API key requirement, chat, editor, or browser. Build one verified path before widening the adapters.
