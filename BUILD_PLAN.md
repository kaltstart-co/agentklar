# Build plan

The old application has been replaced. Git retains its source. This plan describes the new implementation only.

Each harness has separate setup and support. Shared context does not replace native instructions or permissions.

| Harness | Native setup | Worker status |
| --- | --- | --- |
| Codex | MCP, AGENTS.md, project skills | Verified locally |
| Claude Code | MCP, CLAUDE.md, project skills | Implemented; standalone worker login unavailable in tested process; Desktop Code tab is signed in |
| Muse | CLI and native model discovery; MCP, instructions and skills pending | Verified one native worker write and completion; read-only unsupported |

Add a harness in small steps: discover it, read native metadata, verify task and permission behavior, then enable delegation. Instruction and skill setup can follow separately. A detected app or model list does not count as a working adapter.

1. **Current slice:** one local TypeScript service, a small React support UI, durable SQLite records, MCP stdio bridge, explicit projects and roles, and native Codex, Claude Code and Muse worker adapters. Claude’s live worker success remains unverified. One real Muse worker completed an explicit `muse-spark-1.3` task and wrote the expected file. Keep the existing harness as the user's starting point.
2. **Shared context, delivered:** a bounded project brief, manually saved memory, and next steps shared through the local UI and MCP. Revision conflicts keep the UI draft. Each task retains its launch context. Local browser checks and a real Codex worker verified this flow; memory collection is explicit.
3. **Other harnesses:** add Gemini CLI, Cursor, OpenCode and GLM through ZCode workers only after verifying their real native interfaces, authentication, lifecycle, and permission behavior. Muse now has a native stdio worker. Its model list read creates no session or prompt; a separate live worker check verified one file write and completed root turn. Muse read-only work cannot be enforced, and managed MCP setup, instruction editing and skills remain pending. ZCode's app is installed; OpenCode was not found in the local locations checked on 2026-10-01. Discovered CLI or app presence does not prove worker support.
4. **Native project setup:** separate Codex and Claude Code instruction files are supported. The local UI previews guarded edits and undo for root AGENTS.md and CLAUDE.md. Project skills can be installed from one named GitHub skill with a staged preview, then updated from the saved source or removed if every managed file and folder still matches. Updates need a fresh preview and explicit apply; matching trees show Already up to date. A failed update restores the prior tree when safe, or keeps a backup path for manual inspection after a conflict or interruption. Codex uses .agents/skills; Claude Code uses .claude/skills. Add other harnesses, global skills, and plugin bundles only when needed.

   Project skill staging uses pinned [Vercel Skills](https://github.com/vercel-labs/skills) 1.7.0 (MIT) inside a private service folder. Only the reviewed skill folder is copied to the selected project. Its staged lock file is not copied; AgentKlar keeps separate per-harness ownership in SQLite. [Ruler](https://github.com/intellectronica/ruler) (MIT) remains a possible future tool for explicit cross-harness sharing. Its writes can affect .gitignore and MCP setup, so it is not part of this slice.
5. **Model choice:** native Codex, Claude and Muse model lists and explicit model selection are implemented in the local UI and MCP. Deterministic routing uses reviewed Codex and Claude profiles; Muse requires an explicit harness or role and has no inferred cost or quality tier. Native Codex account allowance has initial coverage. Claude and Muse allowance remain unavailable. The policy uses saved cost preference, supplied task complexity, native availability and source-based family profiles. Task and role pins take priority. The main harness can classify the task with its existing model and request automatic routing in `task_start`; the router uses no extra inference. The UI defaults to automatic choice for new tasks and offers manual/native default. LiveBench reference scores can now break comparable policy ties, as described below. Native task quality and subscription savings remain unverified. Keep actual usage separate from estimates; cost preference alone is not evidence of model quality.

   Reuse [models.dev](https://models.dev/api.json), an [MIT project](https://github.com/anomalyco/models.dev), for model specifications and API price references. It does not describe subscription usage or rank model quality. [SWE-bench Bash Only](https://www.swebench.com/) uses a fixed mini-SWE-agent environment for comparable coding scores; other leaderboard entries can mix model and harness effects. [Artificial Analysis](https://artificialanalysis.ai/data-api/docs) provides versioned intelligence, coding, and agent scores, but requires an API key, including its free model endpoint. Core AgentKlar should not require a new paid service. Future benchmark imports must keep the exact model and effort, source, date, method, and version. Missing scores stay unknown; never copy a successor model's score to an older model.

6. **Longer workflows:** linked review → fix → review launches now use completed runs in the same project, a bounded source snapshot, and the same native worker path. The local UI opens an editable draft for each step; MCP can start one linked run explicitly. Local fixtures cover the chain, source boundaries, and routing races. A live Codex chain found and fixed a deliberate decimal bug in a seeded fixture, then reviewed the fix. The initial defective work record was seeded, so this check proves the three linked native steps, not a native build of the starting code. Finished runs can now show an explicit native continuation command through UI or MCP when their saved session and current project state permit it. A saved Codex session was reopened without a prompt and the CLI reached its own folder trust prompt; a continued interactive turn has not been tested. Lead and worker coordination, control transfer, and more worker concurrency remain future work. Avoid a forced completion ceremony.
7. **Reach and setup:** explicit local UI MCP setup supports Codex User scope and Claude Code Local project scope. Settings reads status, previews the exact native command and destination, applies it with a fresh config check, and offers undo only for its unchanged managed entry. The bridge uses absolute Node and installed JavaScript paths with the running service home and port. MCP cannot read or change this setup. Existing entries and other native scopes stay under native settings. A pinned GitHub beta tarball installs the built service and UI with production dependencies only on Node 24 for macOS and Linux. `agentklar start` runs in the foreground. macOS background startup uses a per-user [launchd LaunchAgent](https://support.apple.com/guide/terminal/script-management-with-launchd-apdc6c1077b-5d5d-4d35-9c19-60f2397b2369/mac); `agentklar service` can install, check, open, stop, start and uninstall it. Stopping refuses active work unless forced; restart marks unfinished workers interrupted. Native harness settings and sign-in are untouched. Secure device pairing and remote access remain future work. The hosted UI has no connection to localhost.

Do not add an LLM gateway, API key requirement, chat, editor, or browser. Build one verified path before widening the adapters.

## LiveBench reference evidence

Working: bundled and durable cached scores for reviewed release 2026-06-25, explicit public refresh, Models score details, task-type advice, comparable same-policy tie breaking, and compact chosen evidence in run history. Pins, native allowance and task requirements remain authoritative. No extra inference calls or project data uploads. Max-effort benchmark settings differ from native runs, so native performance and subscription savings remain unverified. Future: reviewed adoption of new releases; automatic release discovery is not implemented.
