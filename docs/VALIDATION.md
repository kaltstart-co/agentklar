## Project folder identity correction

Linux CI run `36887237307` found a real guard failure: deleting and recreating a project could reuse the same device and inode numbers, so a stale native setup preview sometimes applied to the new folder. Native setup and instruction editing now share a folder identity that also includes its creation time. If the filesystem cannot report that time, guarded edits fail safely. Older saved changes with the former two-part identity refuse undo. Deterministic tests cover reused inode numbers with different creation times, normal file edits in one folder, and refusal to undo older records. A prior separate catalog cleanup assertion failed once in CI run `36884393710`; PID validation and mode-specific failure text were added to diagnose a repeat. These tests make no model calls. Final local macOS `npm run check`, all 63 tests, and `npm run build` passed. An isolated Linux Node 24 Docker run passed check, build, and 62 tests with one macOS-only skip. GitHub Linux [run 36888834888](https://github.com/kaltstart-co/agentklar/actions/runs/36888834888) passed check, tests, and build for commit `4a09a356303d1f7e6ddd0a2c8ec8510179009110`.

A later full local test run exposed an empty PID file in the catalog timeout fixture. Its 100 ms deadline could expire while Node started the fixture, before the fixture wrote its PID. The fixture now uses the existing 2,000 ms test probe deadline. Valid child and helper PIDs and both process exits are still required. Focused catalog tests and the next full local run passed; this timing change did not alter the service's production metadata timeout.
