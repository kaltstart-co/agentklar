# Local API

The service listens on 127.0.0.1:4317. UI requests use a local session cookie and an exact allowed Origin. Start the service, open its one-time setup URL, then open the UI at http://127.0.0.1:4317 or http://127.0.0.1:5173. Hosted UI has no local connection.

JSON bodies and replies. Errors: `{error: string}`. IDs are UUID strings. All changes require authenticated UI or the private MCP bearer token, except approval decisions, instruction file changes and native setup writes require the UI cookie and exact local Origin. Native setup reads also require the UI cookie. A valid MCP bearer is rejected for every native setup request, including requests that also carry a UI cookie. Instruction text reads require the UI cookie; MCP receives metadata only.

The macOS service CLI uses separate private `/api/operator/*` routes for authenticated status, a fresh one-use setup link, stop preparation and recovery. They require the saved operator key and managed service ID. Any browser Origin, cookie or Authorization header is rejected, including an MCP bearer. Neither the UI nor MCP exposes these controls. The new setup link expires after five minutes; creating one invalidates an earlier unused link without ending an existing browser session. Stop blocks new task starts before launch and refuses active workers unless `--force`; `start` resumes a service left paused by an interrupted stop command. The CLI checks launchd registration by command exit status and service health through this authenticated route. The human-readable `launchctl print` text is not parsed.

- GET /api/health: `{ok:true}` (public).
- GET /api/snapshot: Snapshot in src/contracts.ts.
- POST /api/projects: `{name,path}` → Project. Path must exist and be absolute.
- PATCH /api/projects/:id: `{preference?,roles?}` → Project.
- GET /api/projects/:id/catalog: cached CatalogSnapshot or null. This never launches a native read. Unknown projects return 404.
- POST /api/projects/:id/catalog: read native model catalogs and Codex account limits for the project folder. Concurrent reads for the same project share one request; completed results have a 30-second in-memory cache. Unknown projects return 404. Both catalog routes require normal local UI or MCP authentication.
- POST /api/projects/:id/recommend: `{roleId?,harness?,model?,complexity?,requiresImages?}` → WorkerAdvice. Complexity is `routine`, `standard` (default), or `hard`; image need defaults to false. Uses service-read native metadata with the same 30-second catalog cache. Unknown project returns 404; unknown role, conflicting harness, unsupported role harness, extra fields or invalid values return 400. No worker starts.
- GET /api/projects/:id/context: `{projectId,revision,brief,memory,handoff,updatedAt,updatedVia}`. Unsaved context has revision 0, empty text and null update fields. Unknown projects return 404.
- PUT /api/projects/:id/context: `{brief,memory,handoff,expectedRevision}` → ProjectContext. All three text fields are required. Limits are 2,000, 4,000 and 2,000 characters respectively. The revision must be a nonnegative safe integer below the maximum safe integer. SQLite checks and saves the revision atomically. A stale writer gets 409 and must read the latest record and review its edits before retrying. The server records update time and authenticated channel (`ui` or `mcp`); clients cannot set them.
- POST /api/tasks/start: `{projectId,prompt,idempotencyKey,roleId?,harness?,model?,readOnly?,includeProjectContext?,routing?}` → Run. `routing:{complexity?:"routine"|"standard"|"hard",requiresImages?:boolean}` asks AgentKlar to select a model and start the worker in the same call; defaults are standard and false within that object. If routing is absent, launch keeps manual/native-default behavior. Harness is `codex` or `claude`; manual launch defaults to the selected role's harness, then Codex. An explicit harness must match the selected role and constrains routing. One active worker per project; busy returns 409. Saved context is included by default; set includeProjectContext to false to opt out.
- GET /api/runs/:id: Run.
- GET /api/runs/:id/context: `{runId,contextSnapshot:ProjectContext|null}`. Inspect the saved context captured at launch; null means no saved text was included.
- GET /api/runs/:id/tail?after=0: `{events:RunEvent[]}`.
- GET /api/runs/:id/result: `{state,result,error,tokens}`.
- POST /api/runs/:id/stop: Run.
- POST /api/approvals/:id: `{decision:string}` → `{ok:true}`. UI only, choices from Approval.decisions.

MCP tools: projects_list, project_register, project_update, project_instructions_list, project_context_read, project_context_update, harnesses_list, models_list, recommend_worker, task_start, run_status, run_context_read, run_tail, run_result, run_stop. `models_list({projectId,refresh?})` uses POST by default; `refresh:false` reads only the existing cache. Context tools use the same validation as HTTP. No approval tool.

CatalogSnapshot contains `projectId`, `checkedAt` and `harnesses`. Each Codex/Claude row contains `harness`, `models`, `modelsStatus`, `modelsMessage`, `modelsTruncated` and `quota`. Models have `id`, `name`, `description`, `resolvedModel`, `isDefault` and `inputModalities`. Native discovery does not prove sign-in, subscription entitlement, model quality or actual charges. Descriptions are vendor text, which can include API prices. Codex models come from app-server `model/list`; Claude models come from the official SDK `supportedModels()` initialization read with waiting empty input, no prompt and no saved session. Both use the registered project folder and native settings. Neither starts a worker or inference. Each probe has a 12-second timeout and terminates only its owned process group.

Quota has `status`, `message`, `ordinaryUsageAllowed` and `buckets`. Each bucket has `id`, `name`, `normalModel`, `primary`, `secondary` and `spendControlReached`. Windows have `usedPercent`, `windowDurationMins` and `resetsAt` in Unix seconds. Unknown values stay null. Reported percentages may exceed 100; clients may clamp a visual bar. Codex reads `account/rateLimits/read` with reset credit details excluded. A nonempty multi-bucket map takes priority over the legacy single bucket, so shared usage is not counted twice. The backend's ordinaryUsageAllowed value is preserved; percentages and reset times do not establish allowance or recovery. Claude quota is unavailable through this SDK read. Catalog and quota failures are independent and use fixed messages. Catalog rows are deduplicated, limited to 100 per harness and bounded in text length; shortened fields, invalid rows or incomplete pagination set modelsTruncated. Quota buckets are limited to 20 with a message when shortened. Model identifiers longer than 120 characters are rejected. Credits, balances, account IDs, emails and raw errors are omitted. AgentKlar stores catalogs only in this service's memory; they do not appear in `/api/snapshot`, the polling flow or SQLite and disappear on restart.

Additional compact reads: GET /api/projects and GET /api/harnesses. Snapshot and run status contain a 300-character prompt preview and a 1,000-character result preview with promptTruncated/resultTruncated flags. Result reads hold up to 24,000 characters with resultTruncated. Event tails fit 24,000 text characters and return `{events,nextAfter,hasMore,truncated}`; individual clipped events have textTruncated. MCP responses fit a bounded context budget and report an explicit truncated preview if a large collection exceeds it.

Each project keeps one latest context record in SQLite. Memory is manually saved text. AgentKlar does not automatically ingest transcripts or files or search vectors. Shared context is separate from the explicit native instruction editor below. At launch, nonempty context is captured as an immutable run snapshot with its revision and update source. Later context edits affect future launches. A run's prompt remains the original task. Both adapters compose the same delimited JSON block of role and project data in the task prompt; native system instructions and permission rules still apply. Project data cannot grant approval or change harness policy. Saved text is capped at 8,000 characters; labels and metadata add a small fixed prompt overhead.

Task launch, idempotent replay, snapshot, run status, result and stop replies include contextRevision (or null) and omit the stored snapshot body. Use the explicit run context endpoint or run_context_read tool to inspect it. A model's own output may quote the context; AgentKlar does not remove text from worker results. Idempotency binds the context inclusion choice, so repeating the original launch returns its original run and captured revision even if project context has changed. Omitted and true inclusion are equivalent; false is a different launch input.

New runs include `harness`. Older runs without it used Codex. Run history may include roleSnapshot, effectiveModel, threadId and turnId when known. Routed runs also store a bounded `routing` record: selected harness/model and pin basis, saved preference, task needs, policy version, catalog time, and short reasons/warnings. The requested `model` and native reported `effectiveModel` remain separate. Claude's native session ID is recorded as threadId; no turn ID is invented. Claude tokens sum input, output, cache read and cache creation counts from the latest final native `modelUsage` once. These query pipeline totals include the main loop, subagents, sidechains and compaction. They exclude helpers outside that pipeline, such as permission classifiers and token probes. Missing, empty or invalid totals stay unknown. Native totals are estimates, not a billing statement; subscription spending remains unknown. Internal ownership fields are diagnostic data; callers do not own the worker process. Preference selects a model only when `routing` is present. A duplicate idempotency key must match the original validated launch inputs, including routing, and replays return the original run without fresh discovery.

Claude workers use the official `@anthropic-ai/claude-agent-sdk` with the installed Claude Code executable, native system prompt, settings and plugins. Discovery checks PATH, `~/.local/bin/claude`, then the newest executable desktop install under `~/Library/Application Support/Claude/claude-code`. Finding an executable does not verify sign-in or subscription access. Sign in through the native Claude Code CLI. AgentKlar does not read or copy login credentials, select an API key fallback, or log native auth events/stderr.

Existing native permission rules still apply. Only unresolved concrete Bash, Edit and Write actions can be answered through the trusted local UI, for that one action. Background commands, disabling the sandbox, requests for outside-path access, MCP questions and other unsupported prompts stop with needs_attention. No approval grants future permissions. A final root result and a drained SDK stream are required for completion; child output cannot complete the run.

Claude readOnly restricts model tool calls to Read, Glob and Grep. A PreToolUse hook denies every other tool, including Bash, MCP, Skill and Agent, before native auto-allow rules apply. Native configured hooks and runtime bookkeeping can still run and write files; this is a tool restriction, not an operating-system sandbox. Codex readOnly uses its native read-only sandbox. Both adapters own detached local process groups, retain PID evidence for a possible surviving group, and terminate their group on stop.


Worker choice is a local policy calculation. The main native harness classifies task complexity and image needs, chooses any team role, and calls `task_start` with `routing:{complexity,requiresImages}` for automatic choice and launch. `recommend_worker({projectId,...})` is a preview only. Responsibility text belongs in the native task prompt; AgentKlar does not classify it using keywords or call another model to route work. The UI defaults to automatic choice for new tasks and also offers preview and manual/native-default launch. A no-choice decision returns bounded reasons and starts no worker. Discovery errors, a changed project, or a busy project require a fresh start request; there is no silent fallback after worker failure.

WorkerAdvice contains `projectId`, `createdAt`, `catalogCheckedAt`, `preference`, `complexity`, `requiresImages`, nullable `choice`, up to three `alternatives`, bounded `reasons` and `warnings`, `policyVersion`, `confidence:"limited"` and official `sources` URLs. Each WorkerChoice contains `harness`, `model`, optional `roleId`, `basis` (`task-pin`, `role-pin` or `policy`), `tier` (`efficient`, `balanced`, `capable` or `unknown`), reasons and warnings. No account record, raw quota, score, cost estimate or claimed saving is returned. Top-level warnings are capped at eight; each choice has at most four reasons and six warnings.

An explicit task model overrides a saved role model. Either pin is preserved exactly, including Claude aliases. A selected role fixes the harness; an explicit conflicting harness returns 400. An explicit model with no role or harness uses Codex, matching task_start. A pin blocked by native allowance, a relevant spend control, missing worker installation or missing required image evidence returns no choice and names the preserved pin. It never selects a replacement. A custom text model missing from the catalog can still receive pin advice with unknown capability and access warnings. Unknown image support cannot satisfy an image request.

Without a pin, advice considers only installed Codex/Claude worker adapters and native offered models. An explicit harness or selected role restricts that set. Exact reviewed model identities determine the policy tier; unfamiliar releases have no inferred tier. Claude aliases use their native resolved model identity for automatic suggestions and tier/quota checks. Unknown aliases, default account alias and unreviewed Fable choices are not automatic candidates. Explicit aliases remain unchanged in pin advice. Codex image support requires `image` in the native input modalities; this Claude SDK does not report modalities, so Claude image support remains unknown.

Policy `2026-10-01.1` targets efficient for routine work, balanced for standard work and capable for hard work. Economical preference targets efficient for routine/standard and balanced for hard. Best targets capable and warns when headroom is low. Balanced preference uses capable for standard/hard when applicable native headroom is at least 50%, and efficient for routine/standard or balanced for hard when it is at most 20%. These thresholds are product rules. Their effect on subscription units is unknown. Automatic hard advice never uses the efficient tier. Candidates prefer the exact target tier, then the nearest reviewed tier; equal fits prefer known native included usage, then reviewed policy order. A lower or higher tier alternative includes a warning. Unknown usage allowance ranks behind a known allowed candidate of equal fit; unknown does not mean free, full, empty or blocked.

The reviewed Codex efficient order is gpt-6-luna, gpt-5.6-luna; balanced is gpt-6.1-sol, gpt-6-sol, gpt-5.6-sol, gpt-5.6-terra; capable is gpt-6-astra. A model is considered only if the native catalog offers it. gpt-5.5 remains unknown. The reviewed Claude efficient order is claude-haiku-4-5-20251001, claude-haiku-4-5; balanced is claude-sonnet-5-5, claude-sonnet-5, claude-sonnet-4-6, claude-sonnet-4-5; capable is claude-opus-5-5, claude-opus-5, claude-opus-4-8, claude-opus-4-7, claude-opus-4-6, claude-opus-4-5. This is product policy order, not measured coding quality. Family guidance was reviewed on 2026-10-01 from [OpenAI model selection](https://developers.openai.com/api/docs/guides/model-selection), [OpenAI latest model](https://developers.openai.com/api/docs/guides/latest-model), and [Claude model configuration](https://code.claude.com/docs/en/model-config).

Native `ordinaryUsageAllowed:false` excludes automatic candidates for that harness. Applicable spend controls also block. Applicable buckets are the shared `codex` bucket with no normalModel, or buckets whose normalModel equals the candidate's offered or resolved identity. Other buckets have no effect. Remaining percentage is the minimum of valid applicable windows with a finite percentage and a future or null reset. Windows with past reset times are ignored with a warning; no recovery is inferred. Metadata discovery and allowance still do not prove model entitlement, native sign-in or exact billing. Coding benchmarks, actual dollar costs and complete Claude quota remain unavailable. The native main harness continues to plan and split tasks.


Native instruction editing handles two files separately: root Codex `AGENTS.md` (`agents`) and root Claude Code `CLAUDE.md` (`claude`). No other file ID or arbitrary path is accepted. These are real project files. Their contents are neither copied into shared context nor injected into task prompts. Native settings, ancestor instructions, overrides and ongoing sessions decide what each harness loads; file presence alone does not prove loading. `AGENTS.override.md` presence produces a metadata warning without reading its contents. Native config, skills and authentication are not parsed or edited.

- GET /api/projects/:id/instructions: InstructionSnapshot `{projectId,checkedAt,files,changes}`. Each file has `{id,path,status,hash,bytes,message}`; status is `present`, `missing` or `unavailable`. This authenticated read is available to the UI and MCP. `project_instructions_list({projectId})` calls this route.
- GET /api/projects/:id/instructions/:file: InstructionDocument `{id,path,exists,hash,text,bytes}`. Trusted UI cookie required; any MCP bearer is rejected even when a UI cookie is also supplied. Missing files return empty text, zero bytes and null hash.
- POST /api/projects/:id/instructions/preview: `{file,text,expectedHash}` → InstructionPreview `{id,projectId,file,path,before,after,beforeHash,afterHash,createdAt}`. `before` is null for creation. Preview changes no file. It expires after ten minutes; this service retains at most 100 previews and discards them on restart.
- POST /api/projects/:id/instructions/apply: `{previewId}` → InstructionChange. Rechecks content and permission bits before saving. Undo text is durable in SQLite before the filesystem change. Preview IDs are one-use and scoped to the project.
- POST /api/projects/:id/instructions/rollback: `{changeId}` → InstructionChange. Restores the previous text and permission bits, or removes a file created by that change. It checks current text and permissions against the saved applied version. External changes return 409 and remain untouched. An already undone change returns 409.

InstructionChange contains `{id,projectId,file,path,createdAt,updatedAt,state,operation,beforeHash,afterHash,message}`. State is `prepared`, `applied`, `rolled_back` or `interrupted`; operation is `apply` or `rollback`. Inventory returns the last 20 metadata records; before/after text appears only in preview responses and the private SQLite journal. At most 50 finished records per project are retained; unfinished/interrupted records are retained for manual review. Restart marks a prepared record interrupted and performs no recovery writes. Explicit undo may recover an interrupted change only when the current file still matches its saved after version.

All instruction mutations use the native approval trust boundary: trusted UI cookie, allowed exact local Origin, and no MCP bearer. Text must fit 32 KiB in UTF-8 and contain valid Unicode text; BOMs are preserved. Reads reject oversized/binary files, symlinks, nonregular files and hardlinks. The registered real project folder is rechecked before writes. Writes use a temporary file, fsync and rename; existing permission bits are preserved, new files honor the service process umask. Ownership, timestamps, ACLs and extended attributes are not preserved. Ordinary hash checks catch observed edits; they cannot lock unrelated external writers through the final rename. No instruction bodies or undo text enter snapshot polling or MCP tools.


## Native MCP connection setup

- GET /api/projects/:id/setup/:harness: SetupStatus for `codex` or `claude`. Reads native settings on demand. Only the trusted UI cookie is accepted. Returns the entry's `missing`, `configured`, `conflict` or `unavailable` state, scope, fixed message, checked time, latest managed change metadata and `canUndo`. It returns no native entry body, native output, full config or active-session health claim.
- POST /api/projects/:id/setup/:harness/preview: `{}` → SetupPreview. The destination must have no `agentklar` entry and no competing native scope. Shows only the app-generated `entry`, native `command`, `configPath`, scope and Claude project `cwd` (Codex has null cwd because scope is User). Saves a ten-minute, one-use in-memory preview. No native write occurs.
- POST /api/projects/:id/setup/:harness/apply: `{previewId}` → SetupChange. Fresh reads compare the destination, project identity, config snapshot and Codex layer versions before running the fixed native add command. Returns success only after a fresh read verifies the expected entry.
- POST /api/projects/:id/setup/:harness/undo: `{changeId}` → SetupChange. Removes only this app's saved, unchanged entry in the original project's selected scope. Existing exact entries are not adopted. External changes and scope conflicts return 409. An interrupted add or undo can be retried explicitly only if the current entry still matches; absent entries are not removed again.

All setup writes require the trusted UI cookie and exact allowed local Origin. A valid MCP bearer is always rejected, including beside a cookie. Bodies are strict and accept no commands, arbitrary native config paths or replacement entries. Unknown projects return 404; unknown harnesses and extra fields return 400. Missing/stale previews or unknown change IDs return 404; observed config conflicts return 409. Unsupported or unsafe config reads return 422; interrupted command operations return fixed 503 messages. Config reads reject files larger than 2 MiB, symlinks, hardlinks, nonregular files and malformed relevant Claude JSON structures.

Codex reads only app-server initialization and `config/read` with `includeLayers:true` in the canonical project cwd. User-layer provenance must point to the expected native home and have no profile. Any other layer's `agentklar` definition blocks setup, even when it matches. No thread or turn starts. Claude reads only the exact project-local `mcpServers.agentklar` entry from its bounded JSON config, and checks global and committed `.mcp.json` definitions for scope conflicts. It does not use `claude mcp get`, which may start an existing server during its health check.

Add and remove use native CLI argv through spawn with no shell. The native CLI owns config serialization and migrations; AgentKlar never replaces a whole native config and does not promise preservation of unknown native keys. Command stdout/stderr fit 64 KiB, Codex config metadata fits 2 MiB and operations have ten-second probe timeouts. Timeout, shutdown and oversized output stop only the owned subprocess group. Native config/output and credentials are discarded. SQLite stores only the app-generated entry, ownership hash, destination, project identity and bounded change state. Prepared changes become interrupted at restart; no automatic recovery writes run. Standard snapshot checks cannot lock unrelated external writers during the native command. Service startup, native session startup and native trust/permissions remain separate work.
